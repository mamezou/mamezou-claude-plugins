# 構成図の作り方

判断に使える図を作る。「何を置くか」より先に「誰が何を判断する図か」を決める。

## 手順

1. 図が要るか決める。構造と接続関係を示すときだけ図にする。文章で足りるなら文章で書く
2. 目的を一文にする。読者、判断事項、見た後の行動。決まらなければユーザーに聞く。推測で描かない
3. 実在する境界を先に置く。AWSならクラウド > アカウント > リージョン > VPC > AZ > サブネット、
   Azureならテナント > サブスクリプション > VNet > サブネットの入れ子。
   構成にない境界を作らない。「通信を検査する」のような役割で箱を作らない
4. 構成要素を左から右に並べ、公式アイコンに置き換える。構成にない要素を足さない
5. 接続線をすべて引く。線種と動作ラベルで経路を区別し、複数の線種を使うなら凡例を置く
6. 装飾を引く。白背景、直角、細線。説明文は本文側へ移す。色は意味を決めた線と枠だけに使う
7. `.drawio` を保存し、`scripts/export-png.sh` でPNGを書き出し、画像を自分で開いて「確認」の項目を見る。
   最後に、図だけを見て判断事項に答えられるか確かめる

## ルール

構造

- タイトルとサブタイトルで主題と判断事項を示す。一部の構成を描いた図を全体の図と誤読させない
- 構成の全体像と通信経路を1枚に入れる。サービス一覧だけ、経路だけの図にしない
- 境界は構成上存在する範囲だけ描く。リージョンサービスをVPCやサブネットの中に置かない。
  外部サービスはクラウド境界の外に置く
- 処理方向は左から右。入力元は左、管理・分析系は右か下
- 収まらないときは文字を小さくせず、要素を減らすかページを分ける
- 途中経過のステータス注記(無効化済み等)は書かない。図は最終形を描く

表現

- 背景色は使わない。白背景と枠線。色は枠線と接続線に限り、意味を決めて使う
  (例: 青=許可、赤=ブロック、グレー=補助)。色だけに意味を持たせず、名称・線種・凡例を併記する
- 角丸と背景色は表す意味がある場合だけ使い、図内で一貫させる。意味のない角丸カードを全要素に反復しない
- 注記は「注記:」など見出し付きの通常の文か、番号付きコールアウト。左に色帯や縦線を置かない
- 公式アイコンを使い、色・形・縦横比を変えない。グループ色は公式の定義があるクラウドでは公式色に
  従い(AWS Cloud `#232F3E`、VPC `#8C4FFF` 等)、定義のないAzureでは白背景と枠線で描く。
  既存/新設などの状態を色で表さず、名称・線種・凡例で示す。同じ階層のアイコンサイズをそろえる
- サービスを文字だけの箱にしない。装飾目的で構成にないアイコンを足さない
- 図中の文章は最小限。構造 + 番号付きの流れ + 短い注記。説明文は本文側へ
- ラベルは読者に合わせる。非専門の読者にはAPI名でなく動作(「差分確認」「反映」)で書く
- 接続線は直線と直角。矢印ラベルには動作を書く(「呼び出す」「ログを配送」)。線の交差を減らす
- 全テキストに同じフォントを明示する。未指定だと書き出し環境の代替フォントで字形と改行が変わる
- `.drawio` を正データにし、PNGは派生物。元データを変えたら書き出し直す

## AIっぽい図の癖と直し方

| 癖 | 直し方 |
|---|---|
| パステルの背景色。同系色の角丸カードを全要素に反復 | 白背景と枠線。角丸と背景色は意味がある場合だけ |
| 左に色帯や縦線を付けた「ポイント」注記 | 見出し付きの通常の文、または番号付きコールアウト |
| 「Client Experience」「〜層」「包括的〜」のような造語ラベル。各要素に一言スローガン | 公式名称と役割の短い名詞。図中の文章は最小限 |
| 役割ごとのグループ分け。VPCを境界ではなく部品として掲載 | 実在する境界だけを入れ子で描く |
| 矢印がすべて同じでラベルなし | 線種と動作ラベルで経路を区別し、凡例を置く |
| 「全体像」「基盤」など判断事項のないタイトル | 何を判断する図かをタイトルとサブタイトルに書く |
| ロゴやアイコンの着色・変形。装飾目的のアイコン追加 | 公式の色と縦横比を維持する。構成にない要素を足さない |
| Scalable / Secure などのピル、キャッチコピー、フッターの標語 | 削る |

AI生成の判定基準ではない。目的を決めずに描くと人の図にも出る。

## AIに描かせる指示の型

```text
<主題>の構成図を作ってください。

読者: <誰が見るか>

この図で判断できるようにすること:
- <判断事項。例: 基準経路とFirewall経由の経路を区別できる>

実構成:
- <実在する境界とCIDR>
- <境界ごとの構成要素>
- <経路。始点、経由、終点>

表現:
- 公式アイコンと公式グループ色を使う。白背景、直角、左から右
- 図中の説明文は減らし、矢印には動作またはフェーズを書く
- 色だけに意味を持たせず、線種とラベルを併用する
- 構成に存在しない要素を追加しない

対象外: <描かないもの>
```

サービス一覧と「見栄えよく」だけの指示は、上の癖がそろった図を生む。

## 確認

- [ ] タイトルだけで主題と判断事項が分かる
- [ ] 図だけを見て判断事項に答えられる
- [ ] 境界が実構成と一致し、実在しない境界の中に置かれたサービスがない
- [ ] 矢印の始点・終点・向きが分かり、線種の意味が一貫している。複数線種なら凡例がある
- [ ] 消しても意味が変わらない装飾・文章・アイコンがない
- [ ] 公式アイコンの色と縦横比、同じ階層のサイズがそろっている
- [ ] 全テキストにフォント指定があり、書き出し後の字形・改行・重なり・文字切れを見た
- [ ] 顧客名、固有リソース名、ローカルパス、個人名を含まない
