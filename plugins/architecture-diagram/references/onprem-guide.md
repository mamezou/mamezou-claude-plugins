# オンプレミス・自宅ネットワーク構成図作成ガイド

## 目的

設計書や手順書に載せるオンプレミスのネットワーク構成図(事務所、店舗、自宅)について、機器の所属と通信経路を正確に示し、資料間で一貫した外観を保つ。

## 基準資料

- 確認項目: `onprem-checklist.md`
- PNG書き出し: `${CLAUDE_SKILL_DIR}/scripts/export-png.sh`
- テンプレート: `${CLAUDE_SKILL_DIR}/assets/template-onprem.drawio`(style文字列はここから写す)

オンプレミスの機器には、AWSやAzureの公式アイコンにあたる単一のアイコンセットがない。本ガイドはDraw.io Desktopが内蔵する次の2セットを使う。どちらのセットも、Draw.io Desktop 30.4.1のCLI書き出しで描画される。

| 対象 | セット | styleの形 |
|---|---|---|
| ネットワーク機器、仮想化ホスト、端末 | Cisco19 | `shape=mxgraph.cisco19.rect;prIcon=<名前>` または `shape=mxgraph.cisco19.<名前>` |
| VMware環境の仮想マシン | VMware(`vvd`) | `shape=mxgraph.vvd.virtual_machine` |

内蔵アイコンを図に使える根拠は、Draw.ioの利用条件に置く。Draw.ioは、第三者が権利を持つアイコンについて、元のライセンスが同梱を許すことを確認済みだと説明している。利用者が作った図については、Draw.ioは著作権を主張しないとしている([draw.ioのREADME「License」](https://github.com/jgraph/drawio/blob/dev/README.md#license))。

Ciscoは、自社が配布するネットワークトポロジアイコンの利用条件を次の一文で示している([Network Topology Icons](https://www.cisco.com/c/en/us/about/brand-center/network-topology-icons.html))。

> You may use them freely, but you may not alter them.

Draw.io内蔵のCisco19が、Ciscoの配布するどの版に対応するかは、Draw.ioの公式資料に記載がない(未確認)。対応する場合にも条件を満たせるよう、本ガイドは内蔵パレットが付ける既定のstyle(図形名と色)を変えない。

## 表現方針

### 枠にする入れ子

オンプレミスの構成には、入れ子が2系統ある。

- ネットワークの入れ子: 拠点 > セグメント(VLANとサブネット)> 機器
- 収容の入れ子: 拠点 > 物理ホスト > 仮想マシン

仮想マシンは両方の入れ子に属するため、2系統を同時に枠にすると枠が交差する。1枚の図で枠にする入れ子は1系統に決める。

- 通信経路や通信制限を判断するための図は、セグメントを枠にする。仮想マシンは所属するセグメントの枠に置く。物理ホストは、スイッチにつながる1台の機器として枠の外に描く。
- どの仮想マシンがどの物理ホストに載るかを判断するための図は、物理ホストを枠にする。セグメントは各仮想マシンのラベルに書く。
- 物理ホストの管理インターフェイスは、所属するセグメントの枠の中に、アイコンのない箱で描く。
- 複数のセグメントに接続する機器(ルーター、L3スイッチ、複数のNICを持つ仮想マシン)は、セグメントの枠の外に置き、各セグメントへ線で結ぶ。

セグメントの枠には、名称、VLAN ID、サブネット、ゲートウェイを書く。構成にないセグメントを作らない。「監視系」のような役割で枠を作らない。

### 色

- 内蔵パレットが付ける既定の色を変えない。Cisco19の機器は `fillColor=#FAFAFA;strokeColor=#005073`、Cisco19の `cloud` は `fillColor=#6B6B6B;strokeColor=none`、VMwareの仮想マシンは `fillColor=#434445;strokeColor=none`。
- 公式のグループ色にあたる定義がない。枠は白背景と枠線で描き、枠内へ背景色を敷かない。
- 次の色を基本とし、図の目的に応じて意味を定義した色を追加できる。
  - セグメントの枠: `#005073`
  - 拠点の枠・有線・無線: `#404040`
  - 拠点外からのトンネル、通信の流れ(許可した経路): `#1565C0`
  - 仮想スイッチ経由の接続・アイコンのない箱: `#666666`
  - 薄い境界線(凡例の枠): `#AAAAAA`
  - 遮断・ブロック: `#CC0000`
  - 背景: `#FFFFFF`
- 信頼度や稼働状態を色で表さない。状態は名称、線種または凡例で示す。

### 枠と注記

- アイコンのない箱は、白背景、直角、グレーの細線を既定値とする。
- 色付きの角丸枠と同系色の薄い背景を組み合わせたカードを、図全体へ反復する表現は使用しない。
- 設計上の前提は、`注記:`などの見出しを付けた1行の通常の本文として配置する。注記の左側に縦線や色帯を置かない。

### アイコン

- 物理機器にはCisco19のアイコンを配置する。VMware環境の仮想マシンには `mxgraph.vvd.virtual_machine` を配置する。VMware以外の仮想化基盤の仮想マシンは、アイコンのない箱で描き、ラベルの先頭に `VM` と書く。物理機器と仮想マシンの描き分けを凡例に書く。
- 動作を確認済みの図形は次のとおり。

| 機器 | style |
|---|---|
| ルーター | `shape=mxgraph.cisco19.rect;prIcon=router` |
| L3スイッチ | `shape=mxgraph.cisco19.rect;prIcon=l3_switch` |
| L2スイッチ | `shape=mxgraph.cisco19.rect;prIcon=l2_switch` |
| ファイアウォール | `shape=mxgraph.cisco19.rect;prIcon=firewall` |
| 仮想化ホスト | `shape=mxgraph.cisco19.rect;prIcon=hypervisor` |
| ストレージ | `shape=mxgraph.cisco19.rect;prIcon=storage` |
| 無線アクセスポイント、中継機 | `shape=mxgraph.cisco19.wireless_access_point2` |
| デスクトップPC | `shape=mxgraph.cisco19.workstation2` |
| ノートPC | `shape=mxgraph.cisco19.laptop2` |
| 携帯端末(タブレット、スマートフォン) | `shape=mxgraph.cisco19.tablet2` |
| インターネット | `shape=mxgraph.cisco19.cloud` |
| VMware環境の仮想マシン | `shape=mxgraph.vvd.virtual_machine` |

図形名は、Draw.io Desktop 30.4.1のCisco19パレットが付ける名前に合わせる。末尾に `2` のない旧図形(`wireless_access_point`、`cell_phone`、`server` など)は現行のパレットにないため使わない。

- 対応するアイコンがない機器(回線終端装置、仮想化していない物理サーバなど)は、近い別の機器のアイコンで代用しない。白背景、直角、グレーの細線の箱に名称を書く。拠点外のサービス(SaaS、トンネルの中継サービス)も同じ箱で描く。
- アイコンのラベルは、役割、型番またはホスト名、IPアドレスの順に書く。アドレスをDHCPで受け取る端末は `DHCP` と書く。
- ルーティング、NAT、DHCP、DNSを担当する機器は、担当する機能をラベルに書く。
- 同じ階層のアイコンサイズをそろえる。縦横比を変えず、切り抜き、反転、回転を行わない。
- 装飾目的で構成に存在しない機器のアイコンを追加しない。
- 図は最終形を描く。撤去予定の機器や作業中の状態を描かない。

### 接続線

オンプレミスの図では、配線と通信を線種で分ける。

- 有線の配線は濃いグレーの実線とし、矢印を付けない。スイッチのポートにつながる線には、スイッチ側のポート、アクセスまたはトランクの別、VLAN IDをラベルに書く。アクセスとトランクの別は、スイッチの設定に従う(仮想化ホストの接続がトランクとは限らない)。スイッチにつながらない線(回線とルーターの間など)には、この3項目を書かない。
- 無線の接続は濃いグレーの点線とし、矢印を付けない。
- 拠点外からのトンネル(VPN、トンネルの中継サービス)は青の破線とし、利用者の側から到達先へ矢印を向ける(接続を張る向きではない)。ラベルには方式の名称を書く。線は、拠点外の端末または中継サービスから、拠点内の終端(VPNルーター、中継用の仮想マシン)へ引く。
- 特定の通信の流れを示す場合は、青の実線に矢印と動作のラベルを付ける。
- 遮断する経路は赤の破線とし、終端を×印にする。
- 物理ホストと各セグメントの間は、仮想スイッチ経由の接続としてグレーの破線で結び、矢印を付けない。物理の配線(スイッチと物理ホストの間の実線)と線種を分け、仮想スイッチ(ポートグループ)であることを1か所にラベルで書く。
- 同じセグメントの枠の中にある機器どうしは、線で結ばない。枠が同じL2に属することを示す。無線APと無線の端末のように、経由する機器を示す必要がある場合だけ線を引く。
- 接続線は直線と直角を基本とし、線の交差を減らす。
- 線種を複数使うので、凡例を置く。凡例には、使用した線種、物理機器と仮想マシンのアイコン、セグメントの枠を載せる。

線のstyleは次のとおり。上の4種類は `template-onprem.drawio` にある。どの線にも `edgeStyle=orthogonalEdgeStyle;rounded=0;html=1;fontSize=11;labelBackgroundColor=#FFFFFF` を共通で付ける。ラベルの色(`fontColor`)は線の色と同じにする。

| 線 | style |
|---|---|
| 有線 | `strokeColor=#404040;strokeWidth=2;endArrow=none` |
| 無線 | `strokeColor=#404040;strokeWidth=2;dashed=1;dashPattern=1 3;endArrow=none` |
| 仮想スイッチ経由の接続 | `strokeColor=#666666;strokeWidth=1.5;dashed=1;dashPattern=4 3;endArrow=none` |
| 拠点外からのトンネル | `strokeColor=#1565C0;strokeWidth=2;dashed=1;dashPattern=8 4;endArrow=block;endFill=1` |
| 通信の流れ | `strokeColor=#1565C0;strokeWidth=2;endArrow=block;endFill=1` |
| 遮断する経路 | `strokeColor=#CC0000;strokeWidth=2;dashed=1;dashPattern=8 4;endArrow=cross;endFill=0` |

### フォント

フォントの規則はAWS構成図と共通とする。全テキスト要素へ `fontFamily=IPAPGothic` を明示する。確認コマンドは `drawio.md` を参照する。

## 基本レイアウト

- ページサイズ: 1400×900
- タイトル: 左上、22ポイント
- 拠点の枠の名称: 16ポイント。セグメントの枠の名称: 14ポイント
- 機器のラベル: 12ポイント。線のラベル・凡例の項目: 11ポイント。凡例の見出し・注記: 12ポイント
- 左から、拠点外(インターネット、拠点外の端末、拠点外のサービス)、回線終端装置、ルーター、L3スイッチ、セグメントの枠の順に並べる。
- セグメントの枠は右側に縦に積む。拠点外からのトンネルの終端があるセグメントを一番下に置くと、トンネルの線が他の線と交差しない。
- 物理ホストはスイッチの下に置き、各セグメントへ右向きに線を引く。

図の内容が収まらない場合は文字を小さくせず、要素数を減らすかページを分ける。仮想マシンが多いセグメントは、判断に関わらない仮想マシンを1つの箱(「検証用の仮想マシン 6台」)にまとめる。

## 公開範囲

- 非公開の設計書に載せる図は、ホスト名とプライベートIPアドレスを書く。機器の所属と経路を判断する図では、この2つが判断の材料になる。
- 公開する図、社外へ出す図には、顧客名、固有の拠点名や機器名、グローバルIPアドレス、MACアドレス、SSID、住所や設置場所、個人名、取得済みのドメイン名、ローカルパスを書かない。プライベートIPアドレスとホスト名は例示用の値に置き換える。

## 作成手順

1. 本ガイドと `onprem-checklist.md` を読む。
2. 図の目的と読者が確認する判断事項を一文で定義する。
3. 枠にする入れ子を1系統に決める。
4. 事実を、稼働中の機器から取得した設定から集める。スイッチの設定(VLAN、ポート、DHCP)、ルーターの設定、仮想化ホストの仮想マシン一覧を見る。設計書と取得した設定が食い違う場合は取得した設定を採り、食い違いを報告する。
5. 拠点の枠とセグメントの枠を配置する。style文字列は `${CLAUDE_SKILL_DIR}/assets/template-onprem.drawio` から写す。
6. 回線からL3スイッチまでを左から右へ並べ、機器をセグメントの枠へ置く。
7. 有線、無線、仮想スイッチ経由の接続、トンネルの順に線を引き、凡例を置く。
8. 構造と線で表せず、判断を変える前提があるときだけ、見出し付きの1行の注記で追記する。なければ書かない。
9. draw.io元データを保存し、PNGを書き出す。
10. `onprem-checklist.md` に沿ってPNGを目視確認する。

## 保存と書き出し

書き出しの規則はAWS構成図と共通で、コマンド、環境変数、必要なソフトウェアは `drawio.md` に記載する。

- draw.io元データとPNGは同じ基底名にする。draw.io元データを正とし、PNGは掲載用の派生成果物として扱う。
- PNGは `${CLAUDE_SKILL_DIR}/scripts/export-png.sh` で書き出す。スクリプトは、既定では図を1400×900ピクセルの白背景へ配置し、出力寸法を検証する。
- PNGを書き出した後、解像度、文字切れ、線、アイコン、重なりを目視確認する。
