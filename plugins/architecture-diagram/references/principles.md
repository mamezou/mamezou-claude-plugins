# 構成図の原則

クラウド構成図を作るときの共通の原則。AWS構成図を作るときは `aws-guide.md` を先に読み、
色・アイコン・レイアウトの指定が食い違う場合はそちらを優先する。

## 作図の原則

- **目的を明確にする**: 誰が何を判断するための図か。リソース一覧ではなく、伝えたいことが一目でわかるレイアウトにする
- **構成の全体像と通信経路の両方を1枚に**: サービス一覧だけでも経路図だけでも不十分
- **入れ子構造で階層を表現**: Azureなら Subscription > VNet > サービス群、AWSなら アカウント > VPC > サブネット。公式アイコンを枠に添えて何の枠かを明示する
- **ステータス注記はノイズ**: 構成図は最終形を描くもの。「無効化済み」等の途中経過は不要
- **接続線を省略しない**: アイコンを置くだけでなく、通信の流れ(矢印)がないと関係性が伝わらない
- **図を作るのは構造・接続関係を示す場合に限る**: テキストを枠に入れて並べただけの図を作らない。文章で足りる内容は文章で書く
- **図中の文章は最小限**: 構造 + 番号付きの流れ + 短い注記で構成し、説明文は本文側へ書く。文章の多い図は読者に伝わらない
- **読者に合わせたラベル**: 読者が非専門の場合、図中ラベルは正式なAPI名・機能名でなく日本語の動作(「差分確認」「反映」)で書く
- **主題をタイトルで示す**: 図単体で「何の図か」が伝わるタイトルと説明を付ける。主題を誤読させない。過去に、一部の構成だけを描いた図が「全体の図」と誤読される問題が起きた
- **図中のテキストは体言止めか短い動作の名詞句で書く**: 文で書かない(「画面をブラウザへ渡す」→「画面の配信」、「認可コードをトークンへ交換する」→「認可コードのトークン交換」)
- **主語を省いた断定文と、読者へ語りかける言い方を書かない**: 「残るのは cookie 1つ」「ブラウザは届かない」のような語り口を使わない
- **1つの注記は1行に収める**: 2文以上に分けない。分けたくなったら本文側へ移す
- **図のタイトルは名詞句にする**: 問いの形にしない(「ログインでトークンがどこに残るか」→「ログインとアクセストークンの保管先」)

## デザイン

- **背景色は使わない**: 公式アイコンでサービスの種類がわかるので、ネットワーク境界の背景色で区別する必要がない。白背景 + 枠線のみ
- **色は枠線と接続線で最小限に使う**: 青=通信許可、赤=ブロック、グレー=補助情報
- **生成AI感を避ける**: パステルカラーの背景色は避ける

AWS構成図では、AWS公式グループ色の使用を認めている。`aws-guide.md` の指定に従う。

## フォント

- すべてのテキスト要素に同じ `fontFamily` を指定する(既定は `IPAPGothic`。書き出しスクリプトの `DIAGRAM_FONT` で変更できる)
- 未指定だとPNG書き出し環境の代替フォントで描画され、中国語フォントの字形が混入することがある(実際に発生した)
- 書き出し環境で使える日本語フォントは `fc-list :lang=ja family` で確認する

## 元データとPNG

- `.drawio` が正データ、PNGは掲載用の派生成果物。両方を同じ基底名で置く
- `.drawio` を変更したらPNGを出力し直す
- 書き出しは `../scripts/export-png.sh <input.drawio> [output.png]` を使う。1400×900の白背景へ配置し、出力寸法を検証する

1400×900に収まらない図を書き出す場合は、スクリプトを使わずDraw.io Desktopから
ページ単位・余白0・拡大率100%で書き出し、寸法を目視で確認する。

## クラウド公式アイコン

draw.ioにはAWS(`mxgraph.aws4.*` 図形)とAzure(`img/lib/azure2/` のSVG)のアイコンが内蔵されて
おり、通常はダウンロード不要。内蔵セットにないサービスだけ、公式ページからSVGをダウンロードして
埋め込む(埋め込み方は「draw.io SVG埋め込み」参照)。

- AWS: https://aws.amazon.com/jp/architecture/icons/
- Azure: https://learn.microsoft.com/en-us/azure/architecture/icons/

## draw.io SVG埋め込み

- **URLエンコード方式を使う**: `image=data:image/svg+xml,<URLエンコードしたSVG>`
- Base64方式(`data:image/svg+xml;base64,...`)は draw.io で表示されない
- Python: `urllib.parse.quote(svg_text)` でエンコードし、style の `image=` に指定

## 公開前チェックリスト

図を公開資料に載せる前に確認する。AWS構成図は `aws-checklist.md` も使う。

- [ ] タイトルと説明だけで「何の図か」が伝わる(主題を誤読させない)
- [ ] リソース名や構成が、記事本文の記述と一致している
- [ ] アイコンは公式で、埋め込みはURLエンコード方式(Base64は表示されない)
- [ ] 色の使い方が一貫している(青=通信許可、赤=ブロック、グレー=補助情報)
- [ ] 接続線に省略がなく、ラベルに動作が書いてある
- [ ] すべてのテキストにフォント指定がある
- [ ] 途中経過のステータス注記が入っていない
- [ ] PNGを出力し直し、目視で字形・重なりを確認した
- [ ] 顧客名・固有リソース名・社内ホスト名・個人名を匿名化している
