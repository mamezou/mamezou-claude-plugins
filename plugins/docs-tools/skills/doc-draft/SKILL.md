# 長い資料の作成

対象は、設計書・手順書・共有ページなど、チャット文面より長い資料の新規作成と全面的な書き直し。
本体 (Skill を読み込んだエージェント) は、何を載せるかを手順 1〜2 で依頼者と決め、どう書くかを
手順 3〜5 で仕上げる。本体は、載せる中身を依頼者に聞かずに足したり削ったりしない。

## 1. 元の資料を調べ、載せる中身の一覧を作る

本体は、覚えている内容や、タスク表・作業の記録の要約から書き始めない。書く前に、資料の元になる
資料を調べる。

- 依頼の原文を開く。手元にないときは、置き場所を依頼者に聞く
- `docs-tools:repo-survey` に調査を依頼する。依頼文には次を書く
  - 資料の題名、読者、依頼の原文
  - 探す範囲: 相手へ送った文面、作業の記録、旧版と関連する資料、手順書。置き場所が分かるものは
    パスで示す。題名の主な語で、内容も検索させる
  - 返すもの: 読者ごとの作業 / 読者の間で受け渡す情報 / 相手と合意した事項と相手の要望 /
    過去に起きた失敗とやり直し / 資料どうしで合わない記述。1 行ごとに、出典 (パスと行) と原文を付けさせる
  - 相手へ送った依頼や手順の文面にある設定項目と受け渡す値は、項目ごとに 1 行で全部返させる。
    似た項目をまとめさせず、行数の上限も付けない (まとめると、項目が抜ける)
  - 読んだ資料と、見つけたが読んでいない資料も返させる
- 本体は、返った行を「載せる中身の一覧」にし、1 行ずつ次の 3 つに分ける

| 区分 | 入れるもの |
|---|---|
| 載せる | 読者が資料だけで作業するのに要る内容 |
| 載せない | 依頼者が載せないと決めた内容。読者の作業を変えない経緯と説明 |
| 依頼者が決める | 載せるかどうかで資料の範囲が変わる内容。頼まれていない論点。資料どうしで合わない内容 |

- 「載せる」に分けた行は、本体が出典を開いて確かめる。確かめられなかった行は「依頼者が決める」へ移す
- 元の資料がない題材では、依頼者の発言と公開されている資料から一覧を作り、出典を付ける

## 2. 中身の判断を、依頼者へ 1 回で聞く

本体は、本文を書く前に、一覧を元に依頼者へ聞く。

- 見せるもの: 載せる中身の要約、載せないもの、「依頼者が決める」の各項目。既存の版があるときは、
  どこがどう変わるかを、変更前と変更後の現物 (文・表) で見せる
- 「依頼者が決める」の項目には、答えで資料の何が変わるかと、推奨を 1 つ付ける
- 依頼者の答えが出るまで、本文を書かない
- 答えが出た後、本体は「載せる」を足しも削りもしない。書いている途中やレビューで新しい論点が
  出たら、足さずに依頼者へ聞く
- 分量は一覧で決まる。本体は字数の上限を先に決めない

## 3. 指示書を作り、書き手に書かせる

本体は `${CLAUDE_SKILL_DIR}/templates/brief.md` を複製し、`<...>` の説明と「例:」の行を資料の内容で
置き換えて指示書にする。書き手は指示書だけを読んで書く。

- 載せる中身: 一覧の「載せる」の行を、出典を付けたまま全部写す。本体が要約して減らさない
- 載せない内容: 一覧の「載せない」の行と、手順 2 で依頼者が載せないと決めた内容を写す
- 文の書き方: 依頼者が退けた文があるとき、原文と退けた理由の言葉を言い換えずに引く

本体は自分と別のエージェントを書き手にし、指示書だけを渡して白紙から書かせる。書き手が前の版の
文に引っ張られないよう、既存の版は読ませない。書き手の数は基本 1 者。次のどれかに当たるとき、
本体は書き手を 2 者にし、同じ指示書を渡して別々に書かせる。

- 依頼者が品質を強く求めた
- 依頼者に退けられた資料を書き直す
- 先方へ出す設計書を書く

2 者目は別のモデルのエージェントでも外部の CLI でもよい。外部の CLI を使うかどうかは利用側の
決まりに従う。

依頼者が受け入れた版に中身を足すだけのときは、書き手に書かせない。本体が、受け入れられた文を
変えずに、足す中身だけを書き入れる。

## 4. 1 本に仕上げる

書き手が 2 者のとき、本体は 2 案を書き手の分からない名前 (案 1・案 2) にして `docs-tools:doc-review` へ
渡し、読者として読み比べさせる。依頼文には、読者の名指し (指示書の「読者と、読んだ後にすること」を
写す) と、返すもの (土台にする案と、もう一方の案から採る箇所) を書く。本体の見立て (どちらがよいか、
どこが弱いか) は書かない。

本体は土台にする案へ、もう一方の案から採る箇所を入れて 1 本にする (書き手が 1 者のときは、返った案が
土台になる)。

- 指示書の「載せる中身」にない内容は削る
- 「載せる中身」の行が本文に全部入っているかを、1 行ずつ確かめる
- 文を直すときは `/docs-tools:draft-precheck` の「直す手順」と「自然な文の見本」に従う

## 5. 確かめる

本体は仕上げた版に `/docs-tools:draft-precheck` を通す。機械の検査に加えて、次の 2 つを
`docs-tools:doc-review` へ依頼する。

- 読者としての通し読み: 前の版も途中の案も読んでいない、初見の読者役に読ませる
- 元の資料との照らし合わせ: 手順 1 で調べた資料のパス、依頼の原文、一覧の「載せない」を渡す。
  指示書と、本体の見立ては渡さない

どちらの依頼でも、「出してよい」などの全体の判定は返させない。本体は、返った指摘の中身で直す。

| 指摘 | 扱い |
|---|---|
| 読者がつかえる箇所 | 直す |
| 元の資料と合わない記述、裏づけのない記述 | 現物で確かめて直す |
| 元の資料にあって資料にない内容 | 一覧の「載せる」にあった行だけ足す。それ以外は足さず、依頼者へ伝える |
| 注意書きや説明を足す提案 | 足さない。読者が作業を進められない欠落だと本体が考えるものは、依頼者へ聞く |

指摘を反映した版には、読者としての通し読みをもう一度通す。

## 6. 依頼者に見せる

本体は、手順 5 を済ませた版を依頼者に見せる。文の直しの途中の案を見せて聞かない。中身の判断は、
手順 2 で聞いてある。

報告に書くこと:

- 仕上がった版の場所
- 手順 2 で決めた中身のうち、入れられなかったもの
- レビューで挙がったが足さなかった内容の件数と、主なもの
- 確かめていない事項

依頼者から書き方の指摘を受けたら、`/docs-tools:draft-precheck` の「直す手順」に従い、同じ種類の
箇所を全文で数えてから直す。

## 関連

- 短い送付文面の作成は `/docs-tools:send-draft`
- 書いた後、送る前の検査 (grep、主語と述語の確認、通し読み、元の資料との照らし合わせ、長文資料の構造) は
  `/docs-tools:draft-precheck`
