# <資料の題名>を白紙から書くための指示書

## 1. 何を書くか
<資料の種類と題名、資料が伝えることを 2〜3 文で書く>
例: 社内向けの手順書を 1 本、白紙から書く。題名は「アプリの利用者を追加・削除する手順」。

## 2. 読者と、読んだ後にすること
<読者ごとに、知っていることと、読んだ後にする作業を書く>
例: 読者は利用者を管理する担当者。認証の基本は知っている。読んだ後、申請に沿って利用者をグループへ追加する。

## 3. 依頼者が決めたこと (変えない)
<依頼者が決めた方針と呼び方を箇条書きにする>
例: 担当者はアプリを使える人をグループへの割り当てだけで絞る。担当の呼び名は「管理者」とする。

## 4. 載せる中身 (ここにない論点を足さない。ここにある論点は省かず、重複と細部はまとめてよい)
<「載せる中身の一覧」の「載せる」の行を、出典と「欠けると止まる読者の判断・作業」を付けたまま写す>
例: 割り当ては入れ子のグループへ及ばない。担当者は利用者をグループの直接のメンバーにする。(出典: 運用の記録 12 行)

## 5. 載せない内容
<一覧の「載せない」の行と、依頼者が載せないと決めた内容を書く>
例: 管理者だけに当てはまる例外、ライセンスの前提、動作確認の手順、作業の経緯。

## 6. 文の書き方
<依頼者が退けた文があれば、原文と、退けた理由を述べた依頼者の言葉を引用し、同じ型の文を書かないよう求める。依頼者が過去に承認した同じ種類の資料があれば、その資料名と、採る構成・言い回しの特徴を書き、実例にある事実は本文へ持ち込まないよう求める。下の要点は残す>
例: 退けられた文「作業と担当は、次のとおり。」。依頼者の言葉「表を見れば分かることを文で繰り返している」。
- 人の操作は操作する人を主語にして動作を書く。仕組みの説明には人を足さず、何がいつどうなるかを書く
- 表やリストの題は見出しに書き、題を言い直すだけの文は置かない
- 理由と動作は 1 文にまとめる。同じ主語の文はまとめ、主題の直後の読点を毎回は打たない
- 並べて読む事項 (手順、条件、場面ごとの操作、受け渡す項目) は表か箇条書きにする
- 指示語 (この・その・これ・それ) で前の段落を指さない
- 呼び名に括弧を付けて繰り返さない
- 語は、業務の文書で使う書き言葉で選ぶ (「作成する」「接続する」「完了する」「利用できる」)。話し言葉 (「作りました」「つなぐ」「済ませた」「使えます」) に言い換えない。漢語の名詞を助詞なしで続けず、体言止めを連続させない

## 7. 体裁
<冒頭の形、章の数、用語の初出の表記、形式を書く>
例: Markdown で書く。章は 4〜5 個までにし、表のセルは短くする。背景は、資料が要る理由から書き始める。

## 8. 出力
<書き手が返すものを書く>
例: 資料の全文だけを Markdown で出す。前置き、解説、選択肢の提示は書かない。
