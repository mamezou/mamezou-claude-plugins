# 計画書を図のページにする

計画書・手順書・検証計画・方針の説明を、読み手がファイルを開かずに判断できるページにする。
`reference/example.html` は、依頼者に「分かりやすい」と評価されたページの構成と部品を使い、題材を架空のものにした例である。

## 手順

1. 元の資料を読む。ページを作り始める前に、読んだ資料の一覧(パス)を示す
2. HTML を書く前に、Artifact ツールを `action: "quickstart"`、`intent: "other"` で呼び、返ってきたページの決まりに従う。このスキルを読む前に呼んでいれば、呼び直さない。quickstart の結果に並ぶ型(Docs・Slides 等)は使わず、ふつうのページとして作る
3. 「ページの構成」の順に節を組み、例の CSS と部品で書く。例にない部品が要るときは、例の色のトークンを使って足す
4. 「載せない情報」を除いてから公開する
5. ページを Slack や Teams のスレッドで相手に渡すときは、「共有用の資料の欄」の手順で、共有用の PDF と投稿の本文を作り、ページの上部に置く
6. 公開したら、リンクとページに載せた節の一覧だけを報告する。共有用の資料の欄を作ったときは、保存とコピーのボタンがページの上部にあることも書く

## ページの構成

節の順番は、読み手が判断に要る順にする。まず、なぜこの作業をするのか(前提)と、何を判断してほしいのか(確認していただきたいこと)を置き、仕組み・段取り・判定・注意を後に置く。見出しは内容に合わせて変えてよいが、この順番の考え方は変えない。元の資料に内容がない節は作らない。

1. 前提: 何のための作業か、今どうなっていて何が困るのか。依頼者から「前提が分からない。その前の話から聞きたい」と指摘があったため、必ず最初に置く。元の資料から前提を読み取れないときは、作る前に依頼者に聞く
2. 確認していただきたいこと: 番号付きの問いと、済・未の状態のチップ
3. 仕組みの図: 今の状態と変えた後を並べて比べる。通信やデータの流れを矢印で示す
4. 作業の順番と理由
5. 日程と実施者: 実施者のチップと、「GO が要る」「夜間」などの印
6. 判定: OK の目安の表と、結果ごとの次の動き
7. 決まっていることと影響、気をつけること

## 文章

ページの文章も、利用側の文章ルール(CLAUDE.md や rules)に従う。harness-ja プラグインを併用している場合は、Output Style「Concise JA」の避ける言葉の表にも従う。加えて次を守る。

- 元の資料にない事実・約束・依頼を足さない
- 整理用のラベル(案A 等)や、工程の数(「全11工程」等)を書かない
- 元の資料で未確認とされている事項は、未確認の印を付けて書く

## 共有用の資料の欄

依頼者が、ページから PDF を保存し、本文をコピーして、そのままスレッドに投稿できるようにする。

- 共有用の版: 依頼者あての節(前提、確認していただきたいこと、施策案や判断の依頼など)を外し、相手に渡す節だけを残す。外す節は、作る前に依頼者に示して可否を得る
- PDF: 共有用の版に印刷用の CSS(`reference/share-box.html` の先頭)を足し、`reference/export_pdf.py` で書き出す。書き出したら、各ページを画像にして1回だけ見る
- 本文: 投稿に添える本文は `/docs-tools:send-draft` で作り、`/docs-tools:draft-precheck` を通す。数字や目標の呼び方は PDF と揃える
- 欄の置き場: ページの見出しのすぐ下に、`reference/share-box.html` の欄を置く。PDF は base64 でページに埋め込み、Artifact の `downloads` 機能で保存させる。公開するときは `capabilities: {"downloads": true}` を付ける
- 直すとき: 元のページを直してから、共有用の版と PDF を作り直す。共有用の版だけを直さない

## 載せない情報

ページは claude.ai に上がるため、次を載せない。

- AWS などのアカウント ID
- パスワード・トークン・秘密鍵
- 社内の IP アドレス
- 個人の連絡先
- 先方から秘密と言われた情報

顧客名・人名は、判断に要る場合だけ載せる。

## 見た目の決まり

- 色は `:root` のトークンで定義する。ダークモードでは、`@media (prefers-color-scheme: dark)` の中の `:root:not([data-theme="light"])` と、`:root[data-theme="dark"]` の両方でトークンを上書きする
- `body` に背景色を付ける
- フォントは Google Fonts だけを使う(例では BIZ UDPGothic と JetBrains Mono)。外部スクリプトは使わない
- 幅 400px 程度のスマホでも、横スクロールが出ないようにする
- `<title>` は2〜4語の名前にする
