# 前のセッションの記録を探す

依頼者が画面で実行して貼った結果、Claude が実行したコマンドの結果、Claude が示したクエリは、
作業ログに残っていないことがある。文面・資料・作業ログに事実を書くエージェントは、書く前にこの
Skill で前のセッションの記録を探し、見つかった箇所から元の資料をたどる。探さずに、同じ調査を
作り直さない。

## 実行

```bash
${CLAUDE_SKILL_DIR}/scripts/session-recall.sh [--project <dir>] [--days N] [--kind <種類>]... [--limit N] <語>...
```

- 語: 渡した語をすべて含む記録を出す。英字の大文字と小文字は区別しない。コマンドの名前、
  テーブル名、エラーの文言、値など、記録に文字のまま残る語を選ぶ。依頼者が結果だけを貼った
  ときに備えて、結果に出る語 (列名、リソース名) でも探す
- `--project`: 案件のディレクトリ。既定は今のディレクトリ
- `--days`: 直近 N 日の記録だけを読む
- `--kind`: 種類を絞る。複数回渡せる。`user` は依頼者の入力、`assistant` は Claude の応答、
  `tool_use` はツールの呼び出しの入力 (コマンドの原文など)、`tool_result` はツールの結果
- `--limit`: 出す件数。既定は 20。今のセッションの記録も対象になるため、前のセッションの記録が
  下に押し出されたときは、件数を増やすか `--days` と `--kind` で絞る

## 読む範囲

- `~/.claude/projects/` の下で、案件のディレクトリのパスの英数字以外 (`/` を含む) を `-` に置き換えた
  名前のフォルダ (例: `/home/user/work/proj` は `-home-user-work-proj`) にある `*.jsonl` と、フォルダの
  下の `subagents/` の記録。環境変数 `CLAUDE_CONFIG_DIR` があれば、`~/.claude` の代わりに
  `CLAUDE_CONFIG_DIR` の下を読む
- 各行の `cwd` が `--project` の下にある行だけを使う。ほかの案件の記録は読まない
- 案件のサブディレクトリで始めたセッションの記録は、別の名前のフォルダに残る。案件のディレクトリで
  探しても出ないため、サブディレクトリを `--project` に渡して探す
- ツールの結果が「Full output saved to: <パス>」で別ファイルにあるときは、別ファイルも読む。
  読むのは上のフォルダの下にあるファイルだけ
- 読むのは、依頼者の入力、Claude の応答の本文、ツールの呼び出しの入力、ツールの結果。Claude の思考、
  会話の要約、ほかのセッションとサブエージェントからの報告、通知は読まない

## 出力

- 一致した記録を新しい順に出す。1 件ごとに、日時 (JST)、種類、セッション ID (サブエージェントの記録は
  サブエージェントの ID も)、記録のファイルと行番号を出す。記録のファイルは、`/docs-tools:draft-precheck`
  の「コードの出どころ」に渡す会話の記録にも使える
- 本文は、一致した行 (先頭に `>`) と前後 2 行。1 行は 200 字まで
- Claude の応答とツールの呼び出しで一致したときは、直後の記録 (依頼者の入力、または呼び出しの
  結果) の先頭 8 行も出す。Claude が示したクエリを依頼者が実行して結果を貼ったときは、貼った結果が
  直後の記録の欄に出る。依頼者の入力で一致したときは、直前の Claude の応答の末尾 8 行を出す
- 鍵、トークン、パスワード、接続文字列らしい値は `***` に伏せる。スクリプトは値の名前と形で
  見分けるため、伏せ字には漏れがある

## 結果の扱い

- 結果は元の資料を探す手がかりで、根拠ではない。文面・資料・作業ログに書く事実は、結果が指す元の
  資料で確かめてから使う
- 依頼者が会話に貼った結果は、依頼者の発言として出典に書き、日時とセッション ID を添えて原文を
  引用する。ファイルは現物を開く。今も同じ値かが要るときは、コマンドを実行し直すか依頼者に聞く
- 見つからないことを、「行わなかった」「なかった」の根拠にしない。Claude Code は古い記録を消す
  (設定 `cleanupPeriodDays`)。別のディレクトリや別の端末で行った作業、画像で貼った結果、語の表記の
  違いでも見つからない。見つからないときは、探した語と範囲を書いて依頼者に聞く
- 出力を文面へそのまま写さない。出力には、伏せ字の漏れ、途中で退けられた案、別の人の発言が混じる。
  使う事実は、元の資料から取り直す

## 使う場面

- 送付文面の設計メモで、相手とのやり取りと使う事実の出典を探すとき (`/docs-tools:send-draft`)
- 長い資料を書く前に、元の資料を探すとき (`/docs-tools:doc-draft`)
- 作業ログに、根拠になった実行を書くとき (`/docs-tools:work-log`)
- 依頼者が「昨日流した」「前に送った」と言ったとき

## 関連

- 文面のコードブロックの各行が会話の記録のどこに出ていたかは、`/docs-tools:draft-precheck` の
  「コードの出どころ」で見る
