# 文章ルール(送付文面の正本)

対象は先方・内部向けの送付文面。返信・チャット文面の文体の正本は Output Style
「Concise JA」(`/config` で Concise JA を選ぶ)。文の書き方・構成・言葉の禁止事項・
括弧と識別子・説明の量・成果物報告の型など返信向けの節は同 Style にある
(送付文面にも同じ基準を適用する)。出典は文化庁「公用文作成の考え方」と指摘の
記録。Stop hook (`response-quality.sh`)は機械化できる部分集合を検知する。

## 禁止語と言い換え

避ける言葉の表は Output Style「Concise JA」の「避ける言葉と言い換え」の1枚が正本。
送付文面にも同じ表を適用する。

## 指示語の置換確認

送付文面の指示語は1通あたり目安2回以下。判定基準は同 Style「指示語の置換確認」。
機械では判定できないため、件別の判定は書き手が行う。全廃への過補正はしない。

## 読者としての通し読み

grep と1文ごとの確認では、検査に通っても同じ形の短い文が並ぶ文章を見落とす。300字を超える
文書(送付文面・手順書・原稿・記事)は Write 確定前に、読み取り専用のサブエージェント
(model: sonnet)へ読者を名指しして頭から通して読ませ、つかえた箇所を挙げさせる。主語と述語の
対応も同じ依頼で見させる。返った指摘は本体が現物で確かめ、段落を単位に直す。文書では
1文60字を目安にとどめ、理由と動作は1文にまとめてよい。分けると同じ形の短い文が並ぶ
場合は分けない。段落は「読み手がこの段落を読んで次に何をするか」で組む。

## 送付文面

送付文面(ドラフト・Notion・exports 配下)の禁止項目(内部パス・ローカル拡張子・
組版記号・外部 AI 言及・禁止語)は `draft-precheck.sh` hook が編集時に検査する。案件の
禁止語は `.claude/harness.json` の `draftPrecheck.bannedTerms[]` に置く。検査項目は
`draftPrecheck.checks` で個別に止められる。
