# 検知ログの週次レビュー

hook が差し戻した記録を、規則と辞書の改善へ戻す。集計はスクリプトで決定的に行い、
判断(誤検知か実違反か、何を直すか)は本文を読んで行う。hook と辞書・閾値の案は、
過去の会話の記録で効くかを確かめてから出す。反映は承認後に行う。

## 手順

1. 集計を実行し、出力を全文読む。

```bash
bash "${CLAUDE_PLUGIN_ROOT}/skills/harness-review/summarize.sh" $ARGUMENTS
```

2. 種別ごとに、直近の検出例を読んで「誤検知」「実違反」「規則の曖昧さ」に分ける。
   判断がつかない例は、検知ログの該当行の前後(同じ時刻帯の作業ログ)を読んでから決める。
   読まずに「誤検知と思われる」と書かない。
3. 分類ごとに対応案を作る。
   - 誤検知: `.claude/harness.json` の辞書から語を外す、閾値を上げる、除外条件を足す、
     `responseQuality.patterns` からパターン番号を外す。hook 本体の正規表現を変える
     必要があるときは、対象の hook 名と変更案を書く
   - 実違反: 既存の文を直すか、hook・手順・テンプレートを変える案を出す。文を足すだけの案は
     出さない。既存の文を直す案は、直す rules か Output Style の節を引用し、変更前と変更後を並べる
4. hook と辞書・閾値の案は、「変更案を過去の記録で試す(replay.sh)」の節に沿って
   `replay.sh` に流す。試す記録は、検知ログの行の `[session:<ID>]` の ID をファイル名に持つ
   記録と、依頼者が指摘した場面を含む記録。場面ごとにラベルを付けて `--labels` で渡し、
   次の2つを確かめる。
   - 再発の記録で止まるか: block のラベルの場面(止めたい場面、実違反の場面)で止まる
   - 正当な記録を止めないか: pass のラベルの場面(止めてはいけない場面、誤検知の場面)で
     止まらない。検出の件数だけでは誤検知の割合が分からないため、ラベルを付けた場面で数える
   止める案(語やパターンを足す)でも、止めなくする案(語を外す、閾値を上げる)でも、
   block と pass のラベルの場面を1件以上ずつ入れる。block の場面で止まらない案と、pass の
   場面で止まる案は、直してから流し直す。直せないときは、流した結果をそのまま確認点に書く。
5. 常に読み込まれる指示の行数を前回のレビューと比べ、増えていれば削る候補を1つ挙げる。
6. 次の型で報告し、反映の可否を仰ぐ。反映前に編集しない。

```
【報告】
- 期間と件数、前期間比
- 種別上位3つと、それぞれの分類(誤検知 / 実違反 / 規則の曖昧さ)

【確認点1】<変える対象の実名(harness.json のキー、hook のファイル名、rules のファイル名と節)>
- 変更前: <現物の断片>
- 変更後: <案の断片>
- 再発の記録で止まるか: <止めた件数> / <block のラベルの件数>(<記録のファイル名と行>)
- 正当な記録で止めた件数: <件数> / <pass のラベルの件数>。例: <時刻・hook・メッセージの1行目>
可否をお願いいたします。
```

   rules と Output Style の文を直す案は `replay.sh` で試せないため、変更前と変更後だけを書く。

7. 承認された項目だけ反映する。hook や辞書を変えたら、変えた理由を hook 冒頭のコメントと
   コミットメッセージに残す。

## 変更案を過去の記録で試す(replay.sh)

`replay.sh` は会話の記録(Claude Code の transcript。
`~/.claude/projects/<プロジェクトのパスの / を - に替えた名前>/<セッション ID>.jsonl`)を読み、
記録の中のツール呼び出しごとに PreToolUse の hook を、Stop の hook が流れた点ごとに Stop の
hook を流し直す。止めた点を1行ずつ(時刻 / session_id / 行 / hook / ツール / メッセージの
1行目)出し、最後に hook ごとの流した回数・止めた回数・エラーの件数を出す。

```bash
bash "${CLAUDE_PLUGIN_ROOT}/skills/harness-review/replay.sh" \
  [--config <harness.json>] [--labels <labels.tsv>] [--hook <hook名>]... <記録.jsonl>...
```

- 辞書・閾値の案: `.claude/harness.json` を一時ディレクトリへ写して案を入れ、`--config` で渡す。
  元の設定と案を入れた写しで1回ずつ流し、結果を比べる
- hook の案: プラグインのディレクトリを一時ディレクトリへ写して hook を直し、写しの中の
  `skills/harness-review/replay.sh` を実行する。`replay.sh` は自分と同じプラグインの hook を
  流す。変更前の結果は元の `replay.sh` で取る
- 応答の文体検査では、止めた点のメッセージの1行目がどのパターンでも `[応答の文体違反]` に
  なり、どのパターンが止めたかは出力から分からない。1つのパターンを試すときは、`--config` の
  写しの `responseQuality.patterns` をそのパターンの番号だけの配列(例: `[19]`)にする
- `--hook` で流す hook を名前で絞る(例: `--hook response-quality`。`.sh` は付けても付けなくても
  よい)。名前は `hooks/hooks.json` の PreToolUse と Stop の hook に限る。すべての hook を流すと、
  記録1本で1分以上かかることがある
- `--config` を省くと、最初に渡した記録に残る cwd から上へ辿って最初に見つかる
  `.claude/harness.json` を使う。cwd の違う記録を一緒に渡すときは `--config` を指定する

ラベルは次の順で作る。

1. ラベルなしで流し、止めた点の時刻・session_id・行を見る
2. 止めなかった場面の行と時刻を、下の `jq` の一覧で探す
3. 場面ごとにラベルの行を書く
4. `--labels` を付けて流し直す

`--labels` のファイルは TSV で、1行に1つの場面を書く。`#` で始まる行、空行、1列目が
`session_id` の見出しの行は読み飛ばす。列はタブで区切るため、`printf` で書くと崩れない。

```bash
printf '%s\t%s\t%s\t%s\n' <セッション ID> 479 block 'TODO.md を読まずに編集' >> labels.tsv
```

| 列 | 内容 |
|---|---|
| session_id | 出力の session_id の列の値 |
| 時刻か行 | 出力の時刻の列の値、または行の列の値 |
| expected | 止めるべきなら `block`、止めるべきでないなら `pass` |
| メモ | 場面の説明 |

行は記録のファイルの行番号で、PreToolUse はツール呼び出しの行、Stop は応答の最後の
assistant の行を指す。止めなかった場面の行と時刻は、次で一覧する。

```bash
jq -rR 'fromjson? // empty | select(.type == "assistant")
  | [input_line_number, (.timestamp // "-"),
     (.message.content[]? | if .type == "tool_use" then "tool_use " + .name
        elif .type == "text" then "text " + (.text | gsub("\n"; " ") | .[0:40]) else empty end)]
  | @tsv' <記録.jsonl>
```

照合の結果は、ラベルの行ごとに「止めるべきを止めた」「止めるべきでないのに止めた」
「止めるべきを止めなかった」「止めるべきでないのを通した」「記録に無い」に分けて、件数を出す。
「記録に無い」は、ラベルの行や時刻が再生の点に当たっていない。ラベルを直して流し直す。
ラベルは、記録の該当箇所を読んでから付ける。Claude が付けたラベルは案として依頼者に示し、
確認を受けてから件数に使う。

`replay.sh` は利用者の本物の検知ログと設定に書き込まない。設定は一時ディレクトリへ写し、
検知ログは環境変数 `HARNESS_DETECTIONS_LOG` で一時ディレクトリへ向ける。

限界:

- ファイルの状態を見る検査は、今のファイルで判定する。過去の時点の状態ではない
  (例: `require-reading.sh` の mode が logs の規則で、既存のファイルの編集か新規作成か。
  `harness-change-check.sh` で、`harness.json` の新規作成か)
- 過去の設定とプラグインの版は復元しない。記録の当時に止まったかとは一致しないことがある
- Stop を流す点は、記録に Stop の hook の実行の記録(`stop_hook_summary` の行)があれば、
  その行の直前だけにする。記録の途中から Stop の hook を入れた場合、入れる前の応答には
  Stop を流さない
- `stop_hook_summary` の行が無い記録では、依頼者の入力の直前、Stop hook の差し戻しの直前、
  記録の末尾を点にし、依頼者の中断の直前は除く。要約で続けたセッションの要約の行の直前など、
  Stop が流れていない点も流すことがある
- PostToolUse の hook(`tool-result-check.sh`)は流さない
- 会話の記録の中で `isSidechain` が true の行は流さない
- サブエージェントの記録(`<セッション ID>/subagents/agent-*.jsonl`)は自動では読まない。
  引数に渡すと、PreToolUse だけを流し、session_id の列はファイル名(`agent-<ID>`)になる。
  実際の実行でサブエージェントの hook にどちらの記録が渡るかは確かめていないため、
  結果は参考にとどめる
- 同じ応答で並べたツール呼び出しは、それぞれの行までを切り出して流す。実際の実行で hook が
  動いた時点に、後ろの行がもう書かれていたかは確かめていない

## 判断の基準

- 同じ検出語が期間内に3回以上出ていて、いずれも文脈上まっとうな用法なら誤検知とみなし辞書から外す
- 同じ種別が2週続けて上位3位に入るなら、規則の文言か Output Style の例示が効いていない。
  禁止語を増やす前に、既存の規則の文か Output Style の例示を直す案を先に出す。文や例を
  足すだけの案は出さない
- 差し戻し上限に達して通過した記録が期間内に5件以上あるなら、その種別の差し戻しは体裁の反復に
  なっている。`responseQuality.patterns` からその番号を外す案を出す
- 変更は1回のレビューで3件まで。効果を次回の件数で確かめてから次を変える

## 完了条件

- 集計出力を読み、種別上位3つに分類と対応案が付いている
- hook と辞書・閾値の案に、`replay.sh` で流した結果(再発の記録で止まるか、正当な記録で
  止めた件数と例)が付いている
- 反映は承認された項目のみで、変更の理由が hook のコメントとコミットメッセージに残っている
