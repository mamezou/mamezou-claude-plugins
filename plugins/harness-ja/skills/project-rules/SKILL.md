# 働き方の決まりをプロジェクトへ入れる

1つのプロジェクトで育てた決まりを、ほかのプロジェクトでも同じ中身で使うための手順。決まりの
正本は、この Skill の `assets/` に置く。プロジェクトごとに写しを書き直さないため、プロジェクトが
増えても中身がずれない。

入れる先は2つある。プロジェクトの指示の欄は、依頼者だけが書き換えられる。メモリは、スレッドが
書ける。この Skill は、指示の欄に入れる文を作って依頼者に渡し、メモリは依頼者の「はい」のあとに
書く。

## ひな形

| ファイル | 中身 | 入れる先 | 対象 |
|---|---|---|---|
| `assets/instructions-core.md` | 調整役の役割、判断の軸、指摘を受けたとき、報告、記録 | 指示の欄 | すべてのプロジェクト |
| `assets/instructions-send-block.md` | 送信は依頼者本人が行う | 指示の欄 | 送信を止めるプロジェクト |
| `assets/instructions-send-allow.md` | 依頼者の「はい」のあとに送る | 指示の欄 | 送ってよいプロジェクト |
| `assets/instructions-repo-addon.md` | リポジトリの決まりとの関係、コミットの流れ | 指示の欄 | リポジトリのある案件だけ |
| `assets/memory-core.md` | 文面の書き方、提案と範囲、宿題の絞り方 | メモリ | すべてのプロジェクト |
| `assets/memory-repo-addon.md` | クラウドと手元のマシンの使い分け、コミットの流れ | メモリ | リポジトリのある案件だけ |

ひな形には、特定の案件の人名、社名、チャンネル名、出来事を書かない。プロジェクトで起きた出来事
(いつ、誰に、何を指摘されたか)は、入れたあとにそのプロジェクトのメモリへ足す。

## 手順

1. 依頼者に、次の3つを1通で聞く。答えが会話やメモリにあるものは聞かない。
   - 依頼者の呼び方(`<呼び名>` に入れる)
   - Claude が人に送信してよいか。止めるなら止める版、送ってよいなら許す版を使う。許す版は、
     毎回文面を見せるか、決まった宛先は任せるかも聞く
   - 決まったことと宿題の記録をどこに置くか(`<記録の置き場>`。リポジトリのファイル、
     共有のドキュメント、メモリのどれか)
2. プロジェクトの今の指示とメモリを読む。指示は会話の最初に渡されている。メモリは、メモリの
   フォルダーの索引と、決まりを書いたファイルを読む。
3. 今あるものが空なら「新しいプロジェクト」、決まりが1つでもあれば「既にあるプロジェクト」の
   手順へ進む。
4. リポジトリのある案件は、「リポジトリのある案件の追加分」も行う。
5. 「確認」を行い、「報告」の形で依頼者に渡す。

### 新しいプロジェクト

1. `instructions-core.md` と、送信の版のどちらか1つを、`<...>` を書き換えてつなげる。冒頭の
   コメント(`<!--` から `-->` まで)は除く。
2. つなげた文を、依頼者がそのまま貼れる形で渡す。貼る場所はプロジェクトの設定の指示の欄。
3. `memory-core.md` の見出しごとに、コードブロックの中身を1ファイルとしてメモリに書く。索引に
   1行ずつ足す。

### 既にあるプロジェクト(足し込み)

上書きしない。今ある決まりを残し、無いものだけを足す。

1. ひな形の決まりを1つずつ、今の指示とメモリに照らし、次の3つに分ける。
   - ある: 同じ中身の決まりが既にある。足さない
   - ない: 足す候補
   - 食い違う: 今の決まりとひな形が逆のことを言っている。今の決まりを残し、依頼者に食い違いを
     1件ずつ示して選んでもらう
2. 足す候補を、そのプロジェクトの言葉(依頼者の呼び方、今ある段落の名前)に合わせて書く。
3. 依頼者に、足す文の一覧を見せる。指示の欄に足す文と、メモリに足す文を分ける。今ある文は
   書き直さない。
4. 依頼者の「はい」のあと、メモリに足す。既にあるファイルは、末尾に行を足し、今ある行は
   消さない。指示の欄に足す文は、依頼者が貼る。
5. 足した行の一覧を、日付つきでメモリの1ファイル(`project-rules-added.md`)に残す。元に戻す
   ときは、この一覧の行だけを消す。

### リポジトリのある案件の追加分

1. `/harness-ja:harness-init` で設定ファイルを作る。既にあれば作らない。
2. 設定ファイルの `sendGate.mode` を、指示の送信の版と同じ側にする。止める版は `"block"`、
   許す版は `"allow"`。`.claude/` の書き換えなので、依頼者の承認の行が要る。
3. `instructions-repo-addon.md` を指示に、`memory-repo-addon.md` をメモリに足す。
4. ほかの案件のリポジトリを、写しの元としてこのプロジェクトに追加しない。追加すると、その
   案件の設定と自動の検査が、このプロジェクトのスレッドにも効く。読むだけのときは、その
   スレッドだけに追加し、起動フォルダーの直下ではなく1つ深いフォルダーに取得する。

## 確認

入れたあと、新しいスレッドで次を確かめる。既に起動していたスレッドは古い決まりで動く。

| 確認 | 方法 | 期待結果 |
|---|---|---|
| 指示が入った | 新しいスレッドに「送信の決まりを1文で」と聞く | 選んだ版のとおりに答える |
| メモリが入った | メモリの索引を読む | 足したファイルの行がある |
| 送信が止まる、または通る(リポジトリのある案件) | 下のコマンド。本物の送信はしない | 止める版は終了コード2、許す版は0 |

```bash
printf '{"tool_name":"mcp__Slack__slack_send_message","tool_input":{},"cwd":"%s"}' "$PWD" \
  | bash "${CLAUDE_PLUGIN_ROOT}/hooks/send-gate.sh"; echo "終了コード $?"
```

リポジトリのないプロジェクトには設定ファイルが無く、送信を仕組みでは止めない。止める版を入れた
ときも、守るのは指示とメモリの文になる。報告にそう書く。

## 元に戻す

- 指示: 依頼者が、足した段落を指示の欄から消す。新しいプロジェクトでも、貼る前の中身を控えて
  おき、空にするのではなく控えに戻す。
- メモリ: `project-rules-added.md` の一覧の行とファイルだけを消す。
- 設定ファイル: `sendGate` の行を戻す。
- プラグインは消さない。プラグインは手元のマシンではすべての案件で共用のため、消すとほかの
  案件の自動の検査も止まる。

## 報告

依頼者への報告は、次の順で短く書く。

1. 何を入れたか(止める版か許す版か、足した決まりの数)
2. 依頼者にしてほしいこと(指示の欄に貼る文、選んでほしい食い違い)
3. 入れなかったもの(既にあった決まり、食い違いで保留にしたもの)
4. 確認の結果。確かめていないことは「未確認」と書く

## やらないこと

- 今ある指示とメモリを、ひな形で置き換えない
- 依頼者に聞かずに、送信の版を決めない
- ほかのプロジェクトの出来事(人名、社名、チャンネル名)を、入れる先のメモリに写さない
