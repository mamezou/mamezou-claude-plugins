## feedback-writing.md

```
---
name: feedback-writing
description: 依頼者の名前で出す文面の書き方(書く前に過去の文面を読む、出す前に見る5点、聞き返さない)
metadata:
  type: feedback
---
- 書く前に、同じ宛先への依頼者の過去の文面を数件読み、参考にした文面のリンクと取った要点を1〜2行添えて案を出す。
- 型: 何をするか・なぜかは地の文で書く。箇条書きは値の並びだけに使う。話題ごとに空行を入れる。
- 依頼してきた相手に聞き返さず「次の内容で進めます」と書く。
- 出す前に見る5点: (1) 各文の主語と目的語 (2) 読み手が知らない語の言い換え (3) 同じ文面の中の矛盾 (4) 頼まれていない情報を入れない (5) 条件分岐は文を分ける。前置きで引っぱらず結論の文を先に書く。
- 検査の重さを文面に合わせる。数行の社内向けの文面に、長い資料と同じ一式の検査をかけない。
```

## feedback-proposals-and-scope.md

```
---
name: feedback-proposals-and-scope
description: 提案は費用と並べる。決定済みの前提を確かめてから作り、指示を原文より広げない
metadata:
  type: feedback
---
- 提案は、各案を費用と並べ、基準からの増加額と割合を書く。
- 設計や質問の前に、記録にある決定と宿題を確かめ、決定済みの前提を聞き直さない。
- 依頼者の指示を原文の範囲より広げない。勧めるときは、記録の記載を確かめて引用する。
- 自分でできないことを依頼者に回さず、できない理由と自分でやる方法を先に示す。
```

## feedback-todo.md

```
---
name: feedback-todo
description: 宿題の一覧の絞り方(こちらに次の一手がある近い作業だけ、議事録から増やしすぎない、完了の定義)
metadata:
  type: feedback
---
- 宿題の一覧には、次の一手がこちら側にあり、2週間以内に動く作業だけを入れる。相手の回答待ちや、要るか分からない作業は入れない。
- 議事録の発言を何でも宿題にしない。足すのは、依頼者の担当と明記され、記録がないものに絞る。
- 「完了」は、関係者に報告して初めて完了と扱う。
```
